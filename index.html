Built-in browser

A browser pane inside the Claude desktop app. Claude reads pages, clicks, types and fills forms in it. It has its own sign-ins, separate from your Chrome.

Websites + web appsmcp__Claude_Browser__*

Claude desktop app
Chat
Browser pane (own sign-ins)
localhost:3000

Use it for

  • Testing the app you are building (localhost)
  • Checking how a public site looks and behaves
  • Phone-width and layout checks
  • Reading console errors and network calls

Pick something else for

  • Pages that need your own login: use Claude in Chrome
  • Native Windows or Mac programs: use computer use

How to work with it

  1. Give the address, or ask Claude to start a preview of your dev server.
  2. Say the job in one sentence.
  3. Claude opens the page, clicks through it and reports what it sees.
  4. Ask it to fix the code, then re-run the same flow to confirm.

Good to know

  • Only works while the desktop app is open and online
  • Follows your “Preferred browser” setting
  • Asks approval for some sites

Claude in Chrome

A Chrome extension that lets Claude work inside your real Chrome, in a new tab, using sites you are already logged into. It can also read console logs and network calls.

Websites + web appsmcp__claude-in-chrome__*

You
Claude+ extension
YOUR Chrome tab
✓ already signed in

Use it for

  • Portals and dashboards behind your login
  • Debugging a page with console and network logs
  • Recording a short GIF of a flow

Pick something else for

  • Plain localhost testing: the built-in browser is safer
  • Native programs: use computer use

How to work with it

  1. Open Chrome with the extension running.
  2. Start your request with “In Chrome”.
  3. Claude opens a new tab. It leaves your other tabs alone unless you ask.
  4. On sensitive sites, read what it plans to do before approving.

Good to know

  • Needs the extension and Chrome running
  • Site permissions are set in the extension
  • It acts as you, so check what you ask

Computer use

Claude takes screenshots of your screen, then moves the mouse and types, like a person would. It works in any program that is on screen, not just browsers.

Desktop appsmcp__remote-devices__computer_*

1 Lookscreenshot
2 Decidewhat next
3 Actclick / type

↺ repeat until the task is done

Use it for

  • Native Windows or Mac programs
  • Jobs that jump between several apps
  • “Look at my screen and tell me what is wrong”

Pick something else for

  • Websites and web apps: browsers are view-only here, use a browser skill
  • Password and payment screens: do those yourself

How to work with it

  1. Link this chat to your computer in the Claude desktop app.
  2. Name the program you want it to use.
  3. Approve access to that program when asked.
  4. Keep your hands off the mouse while it works.

Good to know

  • Needs the Claude desktop app linked to your computer
  • Asks access per app before touching it
  • Slower than a browser skill, because it works by screenshot

frontend-design

No commands and no setup. When you ask for a new UI it makes Claude pick a clear point of view first, then build it.

From Anthropicone instruction page, no commands

Design skillfrontend-design / Impeccable
Claude buildsHTML, CSS, app code
Browser skillopens it and looks
Critique + fixaudit, polish, repeat

↺ loop until it looks right

Use it for

  • You start a new page or app from nothing
  • You want a bold, one-of-a-kind look quickly
  • You do not want files or setup in your project

Pick something else for

  • Reviewing a UI you already have: use Impeccable critique or audit
  • Repeatable steps across many sessions: Impeccable remembers your product

How to work with it

  1. Describe the subject, who it is for and the main job of the screen.
  2. Add “use frontend-design”.
  3. It writes a short plan first: colours, type, layout. Read it and redirect early.
  4. Open the result in the built-in browser and ask for changes.

What it makes Claude do

  • Start from the subject. A kids' toy and a finance dashboard should not look alike. Real content shapes the design.
  • Plan first, then build. Write a small palette (4 to 6 colours), type choices and a layout idea, then check it is not the generic default.
  • Type carries the personality. Choose fonts on purpose, lines under 80 characters.
  • Avoid AI tells. Cream and terracotta pages, identical rounded cards, tiny all-caps labels above every heading, one word highlighted in a headline.
  • Motion sparingly. One good reveal beats effects everywhere.
  • Spend boldness in one place. One memorable element, everything else quiet. Always responsive, keyboard-friendly and readable.

frontend-design or Impeccable?

They overlap on purpose. Impeccable started from Anthropic's frontend-design and added structure on top.

frontend-design

one instruction page, no commands

Feels like: hiring a design lead for one brief.

Pick it when

  • You start a new page or app from nothing
  • You want a bold, one-of-a-kind look quickly
  • You do not want files or setup in your project

Impeccable

1 skill, 24 commands

Feels like: a whole design team with named jobs.

Pick it when

  • You already have a UI to review or improve
  • You want repeatable steps before shipping
  • You work in one project over many sessions

Using both? Fine, and common: let frontend-design set the first direction, then use Impeccable to critique, polish and harden it. If they pull in different directions, say which one wins.

Good to know

  • Overlaps with Impeccable on purpose
  • Gives direction, not a checklist

Impeccable

One skill, called /impeccable. You always type it the same way, then say what you want done and where. It remembers your product in PRODUCT.md and DESIGN.md.

By Paul Bakaus1 skill, 24 commands

Use it for

  • You already have a UI to review or improve
  • You want repeatable steps before shipping
  • You work in one project over many sessions

Pick something else for

  • A quick first draft with no setup: frontend-design is lighter
  • Windows or Mac programs: it has no desktop-program mode

How to work with it

  1. Upload the skill zip (Settings → Customize → Skills).
  2. Open the project you want to improve.
  3. Run /impeccable init once. It writes PRODUCT.md.
  4. Run critique, pick the fixes, then polish before shipping.

How you type it

/impeccable <command> <target>

command what to do: audit, polish, harden…

target where: “checkout”, “the header”, a file

Four kinds of screen

It adjusts how bold to be for each one.

Persuadelanding pages, pricing: win attention
Operateapp screens, dashboards: be clear and fast
Readdocs, articles: be easy to understand
Experienceportfolios, galleries: the work leads

What it steers Claude away from

The “AI-made” look. Impeccable has 59 rules that catch it, and a command line scanner that needs no AI.

Heads-up: telemetry When a new design starts it sends anonymous “which option won” data to impeccable.style. Turn off with npx impeccable telemetry off.

Heads-up: helper program It runs a small helper that downloads once on first use. In a locked-down sandbox it may be blocked; the skill then reads your files directly instead.

Good to know

  • Typing /impeccable alone shows a menu for your project
  • It never runs anything by itself

Every Impeccable command

Write /impeccable before each one. The picture shows the idea; click an example to copy it.

BuildSet things up and plan before coding

init

One-time setup. Asks a few questions about your product and saves the answers in PRODUCT.md so every later command knows your audience and goals.

shape [feature]

Plans the screens and flow on paper first: who uses it, what is on each screen. No code yet.

document

Reads your existing code and writes DESIGN.md: your colours, fonts and spacing in one file.

extract [target]

Finds repeated buttons, colours and spacings and turns them into reusable components and tokens.

craft [feature]

Old name for “build this new thing”. Deprecated: just describe what you want instead.

EvaluateFind out what is wrong

critique [target]

A senior-designer review: is it clear, is the hierarchy right, how does it feel? Gives a scored review.

audit [target]

Technical checks: accessibility, performance and responsive problems. Finds real faults, not opinions.

RefineTune what already exists

polish [target]

The final pass before shipping: tidy alignment, fix small inconsistencies, match your design system.

bolder [target]

Makes a safe or boring design more striking.

quieter [target]

Calms down a design that is too loud or tiring.

distill [target]

Strips it to the essentials. Removes whatever does not earn its place.

harden [target]

Makes it survive real life: errors, very long text, other languages, empty and slow states.

onboard [target]

Designs the first-time experience: welcome steps, empty states, a quick first win.

EnhanceImprove one ingredient

animate [target]

Adds motion that helps, such as feedback and transitions, not decoration.

colorize [target]

Adds smart colour to a grey, flat interface.

typeset [target]

Fixes font choices, sizes and heading hierarchy.

layout [target]

Fixes spacing, alignment and visual rhythm.

delight [target]

Adds small moments of personality and joy.

overdrive [target]

Pushes past normal limits with ambitious effects. Use for showcase pages, not everyday screens.

FixSolve a specific problem

clarify [target]

Rewrites confusing labels, buttons and error messages in plain language.

adapt [target]

Makes it work on other screens: phone, tablet, desktop, and native iOS or Android.

optimize [target]

Finds why the UI feels slow (images, scripts, jumpy layout) and fixes it.

IterateTry options in the live browser

live

Opens your running app. Click any element and get alternatives to try right there.

generate [n] [element]

You name the element, it makes several variants for you to choose from. No manual clicking.

No command matches that. Try a shorter word.

Housekeeping commands

pin <command>Makes a shortcut, so /impeccable pin audit gives you plain /audit. unpin removes it.
hooks on | off | statusTurns the automatic design checker on or off. It scans each UI file after Claude edits it (Claude Code projects).
doctorChecks whether PRODUCT.md, DESIGN.md and config are out of date and offers repairs.
npx impeccable detectTerminal scanner, no AI needed. Point it at a folder, file or web address to list design problems.

Recipes: what to run, in order

Copy the sequence that matches your job. Blue is a browser skill, orange is Chrome, violet is computer use, teal is design, dark is Impeccable.

Build a new web page or app

Plan, build, look at it, then improve it.

init→shape→Claude builds→Built-in browser→live→critique→audit→polish→harden

Make an ugly page better

Find the problem first, fix only that, then finish.

critique→layout / typeset / colorize→Built-in browser→polish

Check before you ship

A final safety sweep.

audit→harden→optimize→adapt→polish

Fix something that only breaks when logged in

Needs your real session.

Claude in Chrome→console + network logs→Claude fixes code→Built-in browser re-test

Review or operate a desktop app

Claude sees your screen and acts on it.

Computer use→screenshots + clicks→frontend-design ideas

Quick bold first draft, no setup

When you just want a strong look fast.

frontend-design→Built-in browser→Impeccable polish (optional)

Coverage gaps to remember

  • Impeccable covers websites, web apps and native iOS / Android. It has no Windows or Mac desktop-program mode.
  • For a desktop program, use computer use to see and operate it, and a design skill for ideas.
  • Your ui-ux-pro-max skill also lists desktop interfaces if you want a second opinion.
